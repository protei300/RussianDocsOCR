# ocr_postprocessing — улучшатель чтения штампа прописки

Модуль берёт CTC-матрицы OCR полей штампа и возвращает те же поля, но исправленные. Для этого он использует:
- **формат поля**: дата, номер, код NNN-NNN;
- **саму CTC-матрицу**: кандидат оценивается по ней целиком;
- **справочники**: КЛАДР/ФИАС и коды подразделений ФМС;
- **связи между полями**: код даёт регион и название подразделения, пункт даёт свои улицы.

Модуль не зависит от сервиса и библиотеки `document_processing`. Нужны только `numpy` и `rapidfuzz`, а для рамок моей сети ещё `opencv`.

## Три входа

| вход | когда | что знает |
|---|---|---|
| `CropImprover.improve(label, probs)` | **один лоскут**, соседей нет (тест лоскутов, поток без штампа) | формат поля, матрицу, словари без контекста |
| `OCRPostprocessor.process_crops(fields)` | лоскуты **одного штампа** от сети Виталия | всё выше и связи полей штампа |
| `OCRPostprocessor.process_boxes(boxes)` | рамки штампа от сети сервиса `fields_m` | то же; так работает эндпоинт сервиса |

```python
from ocr_postprocessing import OCRPostprocessor
from ocr_postprocessing.crop import CropImprover

# один лоскут
imp = CropImprover('E:/Grant/ocr_versions/v4/candidate_T031/onnx')   # папка модели (алфавит из model.json)
imp.improve('issuer_line', probs)
# -> {'raw': 'ОТДЕЛ ПО РОПОСАМ МИГРАЦИИ', 'text': 'ОТДЕЛ ПО ВОПРОСАМ МИГРАЦИИ', 'changed': True, 'rule': 'словарь слов'}

# штамп целиком (лоскуты сети Виталия)
pp = OCRPostprocessor('.../onnx')          # один объект на процесс: справочники грузятся один раз
r = pp.process_crops([{'label': 'date', 'probs': m1, 'id': 1}, {'label': 'addr_line', 'probs': m2, 'id': 2}, ...])
r['fields']   # те же поля в том же порядке: raw, text (улучшенный, в виде штампа), value, changed + свои ключи
r['stamp']    # что поля говорят вместе: date, region, district, locality, street, house, building, flat, code
```

`probs` — выход модели как есть: `[T, C]` (или `[1, T, C]` без первой оси), softmax, столбец 0 — blank, остальные — алфавит из `model.json` по порядку.

Метки полей:
- **сеть Виталия:** `date, addr_line, issuer_line, code, house, flat, korp`;
- **сеть сервиса:** `date, place, street, house, building, flat, code`. Её рамка несёт `probs = [матрица обычной обрезки, матрица обрезки с полем]` и `quad` — 4 угла на штампе.

Модуль не запускает OCR. Матрицы считает модель (`model.onnx`) в коде того, кто встраивает.

## Как исправляется каждое поле

| поле | лоскут (без штампа) | вместе со штампом |
|---|---|---|
| дата | лучший путь CTC, если он строго подходит под регулярку даты и такая дата существует; иначе перебор реальных дат по матрице с «звёздочкой» на шум между частями (`wildctc.best_date`), старт с прочитанной даты; ответ в форме штампа («18 ОКТЯБРЯ 2007 Г.», «21.09.2023») | так же |
| дом, квартира, корпус | регулярка номера; иначе самый вероятный «число [буква] [/число]» по матрице (`decode.best_number`); вид штампа («11-А») сохраняется | так же |
| код | NNN-NNN (буквы-двойники → цифры) и соседи по справочнику ФМС, оценённые по матрице | + согласие с регионом и пунктом |
| строки адреса и «кем выдано» | слово, которого нет в словаре (названия КЛАДР и ФМС, ~150 тыс. слов), заменяется ближайшим словарным (не больше двух букв разницы, не однокоренное, не обрезанное краем), если матрица считает новую строку не намного хуже (`word_margin` = 10) | сначала названия, найденные для этого штампа: регион, район, пункт, улица, название подразделения по коду; потом общий словарь |
| регион, район, пункт | — | куски строки по словам типа («ОБЛ.», «Р-Н», «Г.»), связь по КЛАДР (регион → районы и пункты → улицы), регион из кода, район и город из названия подразделения («В КИРОВСКОМ РАЙОНЕ», «В Г. ТОЛЬЯТТИ»); выбор среди названий справочника по матрице |
| улица | — | улицы найденного пункта (до 150 похожих) и частые названия по стране, оценённые по матрице |

**Главный принцип — не испортить верное.** Справочник подсказывает, но решает матрица. Замена принимается, только если сеть сама допускала такое чтение.

## Справочники в памяти

Используются те же файлы и те же переменные окружения, что у сервиса:

| файл | переменная |
|---|---|
| `service/ml/registration/assets/addressru.zip` | `RDOCS_ADDRESSRU` |
| `fms_unit_2026-09-22.csv` | `RDOCS_FMS_UNIT` |
| `street_names_kladr.json` | `RDOCS_STREET_NAMES` |

Пути можно передать и явно: `References(addressru=..., fms_csv=..., street_names=...)`.

Что держится в памяти:
- архив КЛАДР (27 МБ);
- все 268 тыс. пунктов по регионам вместе с готовыми ключами нечёткого поиска;
- словарь слов.

Индекс пунктов строится один раз (~5 с) и кладётся в `~/.cache/ocr_postprocessing/addressru_index_<sha>.json.gz`; папку можно задать через `RDOCS_REFS_CACHE`. Индекс пересобирается сам, если архив поменялся. Следующие старты:
- около 1 с без словаря слов;
- около 2,5 с со словарём.

Улицы одного пункта разбираются из архива в памяти по запросу: это меньше миллисекунды.

## Скорость

Процессор, один поток:

| вход | медиана | 99 % | максимум |
|---|---|---|---|
| лоскут (`CropImprover`) | < 1 мс | — | ~0,1 с (дата, которую пришлось перебирать) |
| штамп, лоскуты Виталия | 30 мс | — | ~0,35 с |
| штамп, рамки сервиса | 200 мс | 0,6 с | 1,1 с |

Сотни кандидатов (номера 1…999, даты, улицы, коды) оцениваются по матрице одним проходом пачкой. Ответы при этом те же, что при поштучной оценке: проверено на всех 1 237 лоскутах теста.

### Эталон 515 штампов — полный разбор сервиса, метрика сайта

| | все поля | дата | регион | район | пункт | улица | дом | квартира |
|---|---|---|---|---|---|---|---|---|
| без улучшателя | 56,9 | 76,6 | 6,1 | 2,1 | 11,6 | 47,7 | 80,1 | 82,0 |
| улучшатель до подбора 26.11 | 77,4 | 83,2 | 74,5 | 37,0 | 60,4 | 68,4 | 85,6 | 90,0 |
| **после подбора 26.11** | **78,7** | 85,4 | 75,1 | 40,0 | 64,6 | 69,4 | 85,6 | 90,0 |

Обе половины эталона выросли: нечётные 77,1 → 78,2, чётные 77,8 → 79,2.

Что дал подбор 26.11, по шагам (в скобках — сколько полей прибавилось из 3 240):
1. район и город из названия подразделения по коду, пункт федерального города = сам город (+11);
2. перебор даты стартует с прочитанной даты (+11);
3. регион, район и пункт выбираются по матрице (+23);
4. улицы — из пункта, выбранного по матрице, и до 150 кандидатов (+6);
5. сокращение региона отдаётся как написано: «КБР», «ЧР» (+1).

Не помогли:
- дата по обеим обрезкам или только по обычной;
- строгий лучший путь даты обычной обрезки;
- другие запасы улицы;
- все улицы КЛАДР в словаре слов.

Правила подбирались на этих 515 штампах. Это оценка сверху, хотя обе половины и растут одинаково.

## Проверки

```bash
venv/Scripts/python.exe -m pytest ocr_postprocessing/tests -q          # на синтетических матрицах, справочники из assets
venv/Scripts/python.exe -m ocr_postprocessing.bench_crops --probs probs.npz --crops crops.json --alphabet <папка модели>
```

Подбор на эталоне штампов делает `Melnikov/Text_fields/registration_page/field_boxes/pp_tune.py`:
- `cache` — один раз сохраняет рамки и матрицы;
- `eval` — прогоняет улучшатель по кэшу; ручки задаются через `--set имя=значение`;
- `--raw` — считает вариант без улучшателя.

Кэш и ответы получены со штампов, это персональные данные: только на E:.
