# История изменений

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
проект использует [семантическое версионирование](https://semver.org/lang/ru/).

## [1.1.0]

Крупное обновление конвейера: новое поколение OCR, распознавание страницы
регистрации, обновлённые модели и переход на актуальные версии зависимостей.

### Добавлено
- **Распознавание страницы регистрации (прописки) внутреннего паспорта** —
  новый тип документа `INTPASSPORTADDR`: детектор строк адреса с повёрнутыми
  рамками (YOLO-OBB), классификатор «печатный / рукописный» и пословная
  маршрутизация между кириллическим и латинско-цифровым движками. Результат —
  в `result.ocr['Address']` и `result.ocr['Address_has_handwritten']`.
- **Поддержка СНИЛС образца 2019 года** (форма АДИ-РЕГ).
- **OCR второго поколения** — движки `OCRCyrillic` / `OCRLatin` в двух режимах:
  `ocr='accurate'` (по умолчанию) и `ocr='fast'`. Исходные модели остаются
  доступны как `ocr='legacy'`. Декодирование — greedy CTC с масками алфавита
  по стране/письменности.
- **Коррекция остаточного наклона** (`DocDeskewer`) после восстановления
  перспективы и обработка паспорта-разворота (две страницы).
- `Pipeline.warmup()` — явный прогрев моделей до первого реального запроса.
- Параллельный запуск независимых стадий (проверки качества, границы документа,
  разбиение на слова).
- Экспериментальный батчинг слов для v2-OCR на GPU (`ocr_gpu_batch=True`);
  по умолчанию выключен, результат не бит-в-бит совпадает с CPU-путём.
- Автовыбор устройства: `device=None` (значение по умолчанию) — GPU, если
  onnxruntime видит CUDA-провайдер, иначе CPU.
- Образцы документов для двух новых типов (персональные данные скрыты).

### Изменено
- **Единый классификатор `DocTypeAngles`** вместо раздельных Angle90 и DocType;
  модули возвращают стандартный контракт `{model_name: payload}`.
- **Переобучены модели** детекции текстовых полей (с пер-классным NMS) и границ
  документа.
- Центроиды `DocTypeAngles` переведены с pickle на `.npz` — убран вектор
  выполнения кода и зависимость от версии numpy.
- `pipeline.process_img(...)` — канонический способ запуска; вызов
  `pipeline(...)` сохранён как алиас.
- Зависимости подняты до актуальных версий (numpy 2.x, onnxruntime 1.27,
  OpenCV 4.13, OpenVINO 2026.2, scikit-learn 1.9); минимальный Python — 3.11.
- `requirements.txt` разделён на секции: ядро инференса, тесты, скрипты.

### Исправлено
- Модули классификаторов и OCR неверно разбирали батч-обёрнутый результат
  модели — падал конвейер (деление на ноль в проверках качества, ошибка типа в
  постобработке OCR).
- Проверка размытия падала на вырожденном входе и могла ложно забраковать
  документ.
- В конфиге путей моделей отсутствовала запись `DocTypeAngles`.
- `from russian_docs_ocr import Pipeline` не работал — пакет не реэкспортировал
  класс; примеры в README вели к `ModuleNotFoundError`.
- Скрипты запускались только из каталога `scripts/`, установленные
  console-entry-points были неработоспособны.
- Починен и дополнен тест-набор.

### Удалено
- Отдельные модули и модели Angle90 и DocType (заменены на `DocTypeAngles`).
- Форматы моделей CoreML, TFlite и H5 — остались ONNX и OpenVINO.
- Зависимости `tensorflow` и `coremltools` (нужны были только для удалённых
  форматов), а также неиспользуемый `matplotlib`.
- Недостижимый код загрузчика моделей (OCRFV).
