# История изменений

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
проект использует [семантическое версионирование](https://semver.org/lang/ru/).

## [4.0.0] - 2026-08-10

Мажорный релиз: репозиторий стал монорепозиторием — библиотека + референс-сервис
(FastAPI + Vue) + conformance-харнесс + три порта (Go, .NET, Kotlin/JVM);
поддержка свидетельств о рождении (набор весов v4); веса моделей вынесены из
git; лицензия сменена на MIT.

### Ломающие изменения
- **Новая структура репозитория.** Пакет `russian_docs_ocr` и `pyproject.toml`
  удалены; библиотека живёт в каталоге `document_processing/` в корне
  (`from document_processing import Pipeline`) и используется клонированием
  репозитория, а не через `pip install .`. Причина: библиотека, сервис, порты и
  conformance-харнесс развиваются как единое целое, и один репозиторий-снапшот
  честнее полупустого pip-пакета (установка с PyPI остаётся открытым вопросом —
  issue #3).
- **Веса моделей больше не хранятся в git.** После клонирования выполните
  `python scripts/fetch_models.py` (29 файлов, ~225 МБ; SHA-256 каждого файла
  зафиксирован в `document_processing/models.lock.json`, ассеты — под тегом
  [`models-v4`](https://github.com/protei300/RussianDocsOCR/releases/tag/models-v4)).
  Набор весов и версия библиотеки версионируются раздельно —
  [`docs/models-release.md`](docs/models-release.md). Закрытый контур:
  `RDOCS_MODELS_URL` / `RDOCS_MODELS_ROOT`.
- **Лицензия сменена с Apache-2.0 на MIT** (по согласованию с правообладателем;
  подробности — `LICENSE`, `NOTICE`, [`docs/legal-links.md`](docs/legal-links.md)).
  Веса моделей распространяются под той же лицензией MIT.

### Добавлено
- **Свидетельства о рождении** — `BIRTHCERT_1998` и `BIRTHCERT_2004`:
  классификатор типов v3 (обучение с негативами, пороги по классам), детектор
  полей v3 (26 классов, строчные поля), детектор границ v4, OCR-опции и
  сортировка слов в порядке чтения.
- **Референс-сервис** (`service/` + `web/`): FastAPI + Vue, асинхронный REST
  (POST → poll), web-UI с журналом обработки и страницей детализации;
  интеграционный слой с 10 пронумерованными правилами корректности
  (`service/ml/runtime.py`); один Docker-образ на CPU/GPU (non-root).
  Документация — [`service/README.md`](service/README.md).
- **Conformance-харнесс** (`conformance/`): пер-стадийные голдены (44 стадии ×
  7 кейсов), закреплённые за набором весов; пробе-хук `Pipeline.probe`;
  раннер сверяет набор весов с манифестом до сравнения чисел.
- **Три порта библиотеки и сервиса** (`ports/`): Go, .NET, Kotlin/JVM — полный
  паритет 44/44 стадий conformance на CPU и GPU, у каждого свой сервис и
  Docker-образы; уроки портирования — `ports/PORTING-LESSONS.md`, численные
  конвенции — `ports/CONVENTIONS.md`.
- **Borders-first fallback**: если классификатор типа говорит `NONE` на сыром
  кадре — прогнать детектор границ и переклассифицировать кроп; сложные ракурсы
  распознаются с уверенностью 0.98+ ценой одного лишнего вызова детектора
  (+1/100 false-accept на хард-негативах). Плюс отклонение «пустой бумаги» для
  `INTPASSPORTADDR` и пересборка разворота паспорта после фолбэка.
- `SECURITY.md`: границы ответственности оператора персональных данных,
  чек-лист 152-ФЗ; `samples/README.md`: как обезличены образцы;
  [`docs/accuracy.md`](docs/accuracy.md): опубликованные метрики качества.
- Новые типы документов в классификаторе: 11 классов, включая `INTPASSPORTADDR`
  (страница регистрации внутреннего паспорта, отдельный путь адресных строк с
  роутингом печатный/рукописный текст).
- CI: `.github/workflows/` — сборка, тесты и conformance для библиотеки и
  портов; веса CI скачивает по манифесту.

### Исправлено
- POSIX-пути в загрузчике моделей (библиотека не импортировалась на Linux) и
  BOM в конфигах моделей — см.
  [`docs/service-merge-notes.md`](docs/service-merge-notes.md).
- Порог бинаризации маски Borders заново откалиброван под чекпоинт v4
  (`MaskFilter=0.5`): покрытие человеческой разметки 0.991 против 0.942 при
  унаследованном значении — пороги калибруются под чекпоинт, а не наследуются.

## [3.0.2] - 2026-08-01

Патч-релиз: устранена гонка на GPU, из-за которой полный конвейер падал или
намертво заклинивал видеокарту.

### Исправлено
- **Конвейер падал или зависал на `device='gpu'` при конкурентных вызовах одной
  модели.** `_split_words` вызывает `WordsDetector` параллельно по текстовым
  полям через `ThreadPoolExecutor` — то есть дёргает одну CUDA-сессию из
  нескольких потоков. Это либо роняло процесс
  (`CUDA error cudaErrorIllegalAddress` посреди графа), либо заклинивало GPU
  намертво: процесс жив, загрузка 100%, прогресса нет. Воспроизведено
  изолированно — 8 потоков по одной сессии виснут примерно на 200-м вызове.
  Добавлена блокировка **на сессию**, создаётся только при `device='gpu'`:
  повторные вызовы одной модели выстраиваются в очередь, а разные модели
  (`_quality_and_borders_parallel`) по-прежнему работают параллельно. CPU-путь
  не затронут — сбой специфичен для CUDA, а блокировка там лишь стоила бы
  пропускной способности.

  После фикса 2400 конкурентных вызовов проходят за 18 с без сбоев, а полный
  прогон по `samples/` на GPU даёт результат, **идентичный CPU** (CER 0.0151,
  exact 0.9107, тип документа 100%, `Licence_number` 100/112). Цена в пределах
  шума: `_split_words` 45.8 → 51.4 мс, GPU остаётся почти вдвое быстрее CPU.

> Та же болезнь на OpenVINO лечилась в 2.0.1 (`Infer Request is busy`) через
> thread-local infer request. Правило: один ускоритель, много потоков, одна
> сессия — сериализовать.

## [3.0.1] - 2026-08-01

Патч-релиз: доведён до настоящей причины фикс кропа документа из
[issue #10](https://github.com/protei300/RussianDocsOCR/issues/10).

### Исправлено
- **Порог бинаризации маски Borders не пересчитали под переобученный чекпоинт.**
  При деплое новых весов подменили `model.onnx`, а `model.json` оставили как был,
  и `MaskFilter=0.9`, откалиброванный под прежнюю сеть, подъедал маску новой.
  Теперь `MaskFilter=0.5`: покрытие человеческой разметки поднимается с 0.937 до
  0.989, а mean IoU на 80 синтетических сценах со сложным фоном и перекрытиями
  пальцами **растёт** (0.941 → 0.968), галлюцинаций фона и промахов 0%.
- `DOC_MARGIN_FRAC` снижен с 0.02 до **0.01**. Отступ больше не компенсирует
  порог; он лишь воспроизводит небольшой запас наружу, который был у прежней
  модели (1.031 от разметки) и удерживал у края напечатанные серию и номер.

> **Уточнение к 3.0.0.** В прошлом релизе усадка контура объяснялась конвенцией
> разметки синтетики (генератор вырезает из маски перекрытые пальцами участки,
> и модель якобы выучила «видимую часть документа»). Проверка это **опровергла**:
> новая модель недобирает и относительно синтетического GT (0.955), а на снимках
> без рук усадка присутствует на всех 18 из 18 — перекрытия объясняют лишь
> 2.6 п.п. из 8.5. Причина в пороге, а не в обучающей цели.

### Прочее
- Качество на 115 размеченных сэмплах: CER 0.0151, exact 0.9107, тип документа
  100%, `Licence_number` 100/112 — против 0.0145 / 0.9087 / 100% / 99 у
  конфигурации 3.0.0. Разброс в три поля из 1556 — шум.

## [3.0.0] - 2026-07-31

Мажорный релиз: удалено легаси-поколение OCR, устранено дублирование весов между
форматами моделей, исправлена регрессия кропа документа из [issue #10](https://github.com/protei300/RussianDocsOCR/issues/10).

### Несовместимые изменения
- **Удалён легаси-OCR.** `ocr='legacy'` больше не поддерживается и бросает
  `ValueError` с пояснением. Вместе с ним удалены модули `OCRRus` и `OCREngNums`
  (они пропали и из экспорта `pipeline_modules`) и их артефакты
  `models/OCR/{rus,eng+nums}`. Причина: движок делал заметно больше символьных
  подмен, а по CER проигрывал текущему greedy-декодированию — держался только
  ради обратной совместимости. Используйте `ocr='accurate'` (по умолчанию) или
  `ocr='fast'`.
- **Удалены папки `models/*/OpenVINO/`.** `Pipeline(model_format='OpenVINO')`
  продолжает работать и выбирает теперь **движок**, а не другой набор весов:
  OpenVINO читает `.onnx` напрямую. Прямые вызовы модулей с
  `model_format='OpenVINO'` сломаются — используйте `runtime='OpenVINO'`.

### Исправлено
- **Новая модель Borders срезала внешний край документа** ([#10](https://github.com/protei300/RussianDocsOCR/issues/10)) —
  на внутренних паспортах терялась часть серии и номера, напечатанных вдоль
  правого края. Контур переобученных весов систематически теснее прежних (площадь
  0.915 в среднем, по правой стороне вставка внутрь до 3% ширины документа).
  Добавлен отступ наружу на этапе построения четырёхугольника
  (`DOC_MARGIN_FRAC = 0.02`), возвращающий геометрию к уровню старой модели;
  отступ применяется до клипа по границам кадра, поэтому фон захватить не может.
  Отключается через `fix_perspective(..., margin=0)`.
- **OpenVINO работал на устаревших весах.** `.ir`-файлы были копиями ONNX под
  другим расширением и протухали при каждом переобучении: Borders работал на
  весах до переобучения #19, TextFields — до #14. После перевода на общий
  артефакт совпадение форматов по полям OCR выросло до 100%, расхождение по
  площади документа исчезло.
- **Занулены субнормальные веса** в поставляемых моделях (у `DocTypeAngles` их
  было 4.81%). Выходы бит-в-бит идентичны; страховка от CPU без flush-to-zero.

### Прочее
- `models/` уменьшился с 343 до 215 МБ; конвейер грузит 12 моделей вместо 14.
- `ModelInference` принимает явный `runtime`; выбор движка: аргумент → ключ
  `"Runtime"` в `model.json` → расширение файла.

## [2.0.2] - 2026-07-26

Патч-релиз: исправления оркестратора, найденные аудитом кода.

### Исправлено
- **Порог `docconf` сравнивался наоборот.** `DocConf` — это уверенность
  (1.0 — точное попадание), а проверка отбраковывала документ при
  `DocConf > docconf`. В строгом режиме (`low_quality=False`) это отсеивало
  уверенно распознанные документы и пропускало плохие. Значение по умолчанию
  0.5 при этом оказалось откалибровано верно (на 122 изображениях `samples/`
  все реальные документы дают ≥ 0.78, ниже 0.5 — только не-документы), ошибка
  была только в операторе.
- **`timings['total']` суммировал параллельные стадии.** Пять стадий
  проверки качества и детекции границ выполняются одновременно, но их время
  складывалось — итог получался на 30–45% больше реального и не уменьшался от
  распараллеливания. Теперь группа считается один раз по своему времени;
  детализация по стадиям сохранена.
- **Результат OCR затирал распознанный адрес.** `_ocr` присваивал словарь
  поверх `OCR`, куда `_address_lines` уже записал `Address`. Оба пути теперь
  дополняют словарь, а не перезаписывают.
- **Плейсхолдер рукописных строк ломал печать отчёта.** Символы `⟨⟩`
  (U+27E8/U+27E9) отсутствуют в cp1251/cp866, из-за чего вывод результата в
  консоль Windows падал с `UnicodeEncodeError`. Плейсхолдер заменён на
  `[рукопись]`.
- **Деление на ноль в уверенности типа документа.** Когда постобработка не
  находит центроид в радиусе, она возвращает нулевой порог; расчёт
  `1 - dist/thresh` падал. Теперь такой случай даёт уверенность 0.0.

### Удалено
- Мёртвая поддержка форматов TensorFlow (`.h5`, SavedModel, `.pb`, `.tflite`) в
  слое инференса: артефактов этих форматов в проекте нет, а `model_format='TFlite'`
  всё равно падал с `FileNotFoundError`. Поддерживаются `.onnx`, `.ir`, `.mlmodel`.

### Добавлено
- Тесты `tests/test_timings.py` и `tests/test_address_output.py`, закрывающие
  учёт времени параллельных стадий и сохранность поля `Address`.

## [2.0.1] - 2026-07-26

Патч-релиз: восстановлена работоспособность формата `OpenVINO` (#9).

### Исправлено
- `Pipeline(model_format='OpenVINO')` падал при инициализации: конфиг
  `DocTypeAngles/OpenVINO` ссылался на устаревшие центроиды `centers.pkl`
  (pandas pickle), тогда как постобработка принимает только pickle-free `.npz`
  (`ValueError: This file contains pickled (object) data`). Теперь используется
  тот же `centers.npz`, что и в ONNX-варианте. Заодно исправлена опечатка
  `"UnifedModel"` → `"UnifiedModel"` в этом конфиге.
- `RuntimeError: Infer Request is busy` на OpenVINO при обработке документа:
  вызов скомпилированной модели переиспользовал один общий infer request, а
  конвейер запускает проверки качества и детекцию границ параллельно (режим по
  умолчанию `low_quality=True`). Теперь каждый поток получает собственный infer
  request от общей скомпилированной модели; результат распознавания не меняется.

### Добавлено
- Регрессионные тесты форматов моделей (`tests/test_model_formats.py`): каждый
  поддерживаемый формат должен инициализироваться и обрабатывать документ через
  параллельный путь, а каждый `Metric`-выход в `model.json` — ссылаться на
  читаемый pickle-free `.npz`.

## [2.0.0] - 2026-07-23

Крупное обновление конвейера: новое поколение OCR, распознавание страницы
регистрации, обновлённые модели и переход на актуальные версии зависимостей.
Версия мажорная — есть несовместимые изменения, см. раздел ниже.

### Известные ограничения
- Рукописные строки в адресе регистрации **не распознаются**: они определяются
  классификатором и подставляются как `⟨рукопись⟩`, порядок строк при этом
  сохраняется. Распознавание рукописного текста запланировано.

### Несовместимые изменения

- Удалены отдельные модули и классы `Angle90` и `DocType`. Вместо них —
  единый `DocTypeAngles`:
  ```python
  # было
  from russian_docs_ocr.document_processing.pipeline_modules import Angle90
  # стало
  from russian_docs_ocr.document_processing.pipeline_modules import DocTypeAngles
  ```
- Модуль `DocTypeAngles` возвращает единый контракт `{model_name: payload}`
  вместо двух ключей: было `result['DocType']['doc_type']` и
  `result['Angle90']['angle']`, стало `result['DocTypeAngles']['doc_type']`,
  `['angle']`, `['doc_type_confidence']`, `['angle_confidence']`,
  `['warped_img']`. Свойства `PipelineResults` (`doctype`, `angle`,
  `rotated_image`, …) при этом **не изменились**.
- Значения `model_format` `'CoreML'`, `'TFlite'` и формат H5 больше не
  поддерживаются — остались `'ONNX'` и `'OpenVINO'`.
- Модули классификаторов и OCR возвращают распакованный результат: например,
  `OCRRus.predict(img)['OCRRus']['ocr_output']` теперь строка, а не список из
  одной строки (раньше это ломало конвейер).
- OCR-движок по умолчанию — новый (`ocr='accurate'`). На одном и том же входе
  результат распознавания отличается от прежнего. Для прежнего поведения:
  `Pipeline(ocr='legacy')`.
- Минимальная версия Python поднята с 3.8 до **3.11**; пины зависимостей
  подняты через мажорные версии (numpy 1.26 → 2.x, pandas 2.1 → 3.x).

### Добавлено
- **Распознавание страницы регистрации (прописки) внутреннего паспорта** —
  новый тип документа `INTPASSPORTADDR`: детектор строк адреса с повёрнутыми
  рамками (YOLO-OBB), классификатор «печатный / рукописный» и пословная
  маршрутизация между кириллическим и латинско-цифровым движками. Результат —
  в `result.ocr['Address']` и `result.ocr['Address_has_handwritten']`.
- **Поддержка СНИЛС образца 2019 года** (форма АДИ-РЕГ).
- **OCR второго поколения** — движки `OCRCyrillic` / `OCRLatin` в двух режимах:
  `ocr='accurate'` (по умолчанию) и `ocr='fast'`. Исходные модели остаются
  доступны как `ocr='legacy'`. Декодирование — greedy CTC с масками алфавита
  по стране/письменности.
- **Коррекция остаточного наклона** (`DocDeskewer`) после восстановления
  перспективы и обработка паспорта-разворота (две страницы).
- `Pipeline.warmup()` — явный прогрев моделей до первого реального запроса.
- Параллельный запуск независимых стадий (проверки качества, границы документа,
  разбиение на слова).
- Экспериментальный батчинг слов для v2-OCR на GPU (`ocr_gpu_batch=True`);
  по умолчанию выключен, результат не бит-в-бит совпадает с CPU-путём.
- Автовыбор устройства: `device=None` (значение по умолчанию) — GPU, если
  onnxruntime видит CUDA-провайдер, иначе CPU.
- Образцы документов для двух новых типов (персональные данные скрыты).

### Изменено
- **Переобучены модели** детекции текстовых полей (с пер-классным NMS) и границ
  документа.
- Центроиды `DocTypeAngles` переведены с pickle на `.npz` — убран вектор
  выполнения кода и зависимость от версии numpy.
- `pipeline.process_img(...)` — канонический способ запуска; вызов
  `pipeline(...)` сохранён как алиас.
